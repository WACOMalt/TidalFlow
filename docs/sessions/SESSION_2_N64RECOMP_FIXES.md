# Session 2: N64Recomp Function Boundary Fixes

## Summary
Successfully fixed all N64Recomp errors and achieved 1024 functions compiled.

## Root Cause Found (Previous Session)
The codeseg overlay had WRONG VRAM base address:
- **WRONG**: ROM 0xA95E8, VRAM 0x801E0000
- **CORRECT**: ROM 0xA95D0, VRAM 0x801DAFA0

This was verified using:
1. Load_Codeseg assembler which uses `lui $a0, %hi(func_801DAFA0)`
2. ROM byte inspection at offset 0xA95D0 matching the decomp

## Main Issue: Missing Function Boundaries

The syms.toml was auto-generated by spimdisasm, NOT from decomp data. This resulted in:
- Incorrect function sizes
- Missing functions that decomp identified separately
- JAL targets pointing to addresses inside other functions

## Key Learnings

1. **Always use decomp as source of truth** - The spimdisasm auto-generated syms.toml has incorrect function boundaries
2. **VRAM address verification is critical** - A wrong VRAM base causes all overlay functions to be wrong
3. **Some JAL targets are local labels** - Not all JAL targets point to function starts; some point to local labels/trampolines inside functions
4. **Incremental fixing works** - Run N64Recomp, fix one error, repeat
